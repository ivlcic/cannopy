# Hyperparameter-sweep rationale

We used a model-specific, deliberately bounded hyperparameter sweep rather than assuming that a single learning rate would transfer equally well across all encoder architectures. The sweep concentrates on learning rate and dropout because these directly affect fine-tuning stability and generalisation, while the remaining optimisation settings were held constant to make results comparable. The selected values should therefore be understood as a local sensitivity analysis around established fine-tuning settings, not as values prescribed exactly by the original model authors.

| Model | Learning rates | Dropout | Rationale |
|---|---:|---:|---|
| mmBERT-base | \(1,2,3\times10^{-5}\) | 0.05, 0.10 | Brackets the \(3\times10^{-5}\) classification setting in the model card and tests modest head regularisation |
| mDeBERTa-v3-base | \(1,1.5,2,2.5\times10^{-5}\) | 0.10, 0.15 | Finer search around the authors’ \(2\times10^{-5}\) example because this model showed greater optimisation sensitivity |
| XLM-R-base | \(1,2,3\times10^{-5}\) | 0.10, 0.15 | Brackets the conventional \(2\times10^{-5}\) token-classification setting |
| BERTić | \(1,3,5,10\times10^{-5}\) | 0.10 fixed | Samples the substantially wider \(9\times10^{-6}\)–\(10^{-4}\) range used in the original BERTić study |

For mmBERT-base, the official model card reports \(3\times10^{-5}\) for cross-lingual sequence classification and \(2\times10^{-5}\) for a reranking task. We therefore evaluated \(1\times10^{-5}\), \(2\times10^{-5}\), and \(3\times10^{-5}\), covering a conservative setting as well as the region demonstrated by the model authors. The released mmBERT configuration specifies zero classifier and encoder dropout, so classifier-dropout values of 0.05 and 0.10 were introduced as modest regularisation alternatives for the heterogeneous multilingual NER training data. Importantly, these values apply to the token-classification head and do not alter mmBERT’s encoder dropout. See the [mmBERT model card](https://huggingface.co/jhu-clsp/mmBERT-base) and [released configuration](https://huggingface.co/jhu-clsp/mmBERT-base/blob/8c1f42296af5de623b0ad6d3a5ed6a5a1838d82c/config.json).

For mDeBERTa-v3-base, the official multilingual fine-tuning example uses a learning rate of \(2\times10^{-5}\). We consequently centred a finer-grained sweep on this value, testing \(1\times10^{-5}\), \(1.5\times10^{-5}\), \(2\times10^{-5}\), and \(2.5\times10^{-5}\). The smaller increments were chosen because preliminary runs indicated that this model was particularly sensitive to optimisation settings. The released model uses a dropout probability of 0.10, which we compared with the moderately stronger value 0.15. In the Hugging Face mDeBERTa implementation, this setting is represented by `hidden_dropout_prob` and is used by both the encoder and token-classification head; it is therefore more accurately described as model dropout rather than exclusively classifier dropout. See the [mDeBERTa-v3-base model card](https://huggingface.co/microsoft/mdeberta-v3-base), [model configuration](https://huggingface.co/microsoft/mdeberta-v3-base/blob/main/config.json), and He et al.’s [DeBERTaV3 paper](https://arxiv.org/abs/2111.09543).

For XLM-R-base, the sweep of \(1\times10^{-5}\), \(2\times10^{-5}\), and \(3\times10^{-5}\) brackets the \(2\times10^{-5}\) learning rate commonly used in Transformer token-classification examples. The source model’s hidden dropout is 0.10; we retained this value and evaluated 0.15 as a slightly stronger classifier-level regulariser. This narrow range reflects XLM-R’s extensive prior use in multilingual sequence-labelling tasks and avoids an unnecessarily broad search. See the [Hugging Face token-classification guide](https://huggingface.co/docs/transformers/tasks/token_classification), the [XLM-R configuration](https://huggingface.co/FacebookAI/xlm-roberta-base/blob/main/config.json), and Conneau et al.’s [XLM-R paper](https://arxiv.org/abs/1911.02116).

BERTić received a wider learning-rate sweep because its original evaluation used Bayesian optimisation over initial learning rates from \(9\times10^{-6}\) to \(10^{-4}\) and training durations between 3 and 15 epochs. The values \(1\times10^{-5}\), \(3\times10^{-5}\), \(5\times10^{-5}\), and \(10^{-4}\) sample this published interval while keeping the experimental budget manageable. Dropout was fixed at 0.10, matching the released ELECTRA configuration, because the original BERTić optimisation did not provide evidence for a separate dropout search. See Ljubešić and Lauc’s [BERTić paper](https://arxiv.org/pdf/2104.09243), the [model card](https://huggingface.co/classla/bcms-bertic), and its [configuration](https://huggingface.co/classla/bcms-bertic/blob/main/config.json).

All configurations used a per-device batch size of 16 with two gradient-accumulation steps, giving an effective batch size of 32. This is consistent with the effective batch sizes used in the published mmBERT and mDeBERTa examples while remaining feasible on the available hardware. Models were trained for at most 15 epochs, but the final model was selected according to macro-averaged validation F1 over the eight evaluation languages. Thus, 15 epochs constitute an upper training horizon rather than an assumption that the final epoch is optimal.

Warmup ratio (0.06), weight decay (0.01), linear learning-rate decay, and maximum gradient norm (1.0) were fixed across the sweep. Weight decay of 0.01 is used in both the mmBERT example and the standard Hugging Face token-classification recipe. The short warmup period and gradient clipping provide protection against unstable early updates, while fixing them prevents the comparison from becoming a large, difficult-to-interpret factorial search. All models were loaded and trained with FP32 parameters so that differences in numerical precision did not confound the architecture and hyperparameter comparison.

Overall, the sweep contains 24 configurations: six for mmBERT, eight for mDeBERTa, six for XLM-R, and four for BERTić. Its purpose is to verify that conclusions are not an artefact of the previously used \(5\times10^{-6}\) learning rate and to give each architecture a reasonable opportunity to perform well under settings supported by its published examples or source configuration.
